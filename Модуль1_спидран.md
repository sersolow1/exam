# Модуль 1: быстрый маршрут (спидран)

Коротко: **только действия, в оптимальном порядке**. Объяснения, зачем нужна каждая команда, есть в `Модуль1_методичка.md`.

Обозначения:
- ⏳ здесь что-то грузится или перезапускается, **не жди, переключайся** туда, куда указано;
- ✅ быстрая проверка (секунды);
- `ens19/ens20/ens21` — имена интерфейсов со стенда sysahelper. **Сначала проверь свои через `ip a`.**

> ⚠️ Команды вводи руками, с обычными `-` и `'` (на сайте встречаются «длинные тире» и «ёлочки»).
> В EcoRouter работает Tab-дополнение, а `conf t` = `configure terminal`.
> В bash-heredoc (`<<EOF`) **не нажимай Tab**: сработает автодополнение. Используй пробелы.

## Почему порядок именно такой

Самые долгие операции: `apt-get` на ISP (iptables, tzdata), `apt-get install bind` на HQ-SRV и перезагрузка HQ-CLI.
Цепочка зависимостей такая:

```
ISP получил интернет ──► apt на ISP (⏳) ──► iptables NAT на ISP ──┐
                                                                  ├──► HQ-SRV apt bind (⏳) ──► DNS
Теги VLAN в PVE + ВСЯ настройка HQ-RTR (NAT, маршрут, VLAN) ──────┘
```
Поэтому:
1. PVE-теги делаем первыми, это 30 секунд.
2. На ISP запускаем apt как можно раньше и, **пока он качает**, целиком настраиваем оба роутера.
3. HQ-CLI отправляем в перезагрузку и, **пока он грузится**, настраиваем серверы.
4. HQ-SRV запускаем на установку bind и, **пока он качает**, настраиваем BR-SRV.

| # | Где | Что | Параллельно (пока ждёшь) |
|---|---|---|---|
| 1 | PVE | теги VLAN 100/200 | — |
| 2 | ISP | имя, сеть, forwarding, **запуск apt** | ⏳ → шаги 3–4 |
| 3 | HQ-RTR | всё сразу (11 блоков) | ISP качает |
| 4 | BR-RTR | всё сразу | ISP качает |
| 5 | ISP | iptables, timezone | — |
| 6 | HQ-CLI | имя + NM + DHCP + TZ, **reboot** | ⏳ → шаги 7–8 |
| 7 | HQ-SRV | имя, IP, юзер, ssh, TZ, **запуск apt bind** | ⏳ → шаг 8 |
| 8 | BR-SRV | имя, IP, юзер, ssh, TZ | bind качается |
| 9 | HQ-SRV | конфиг BIND, запуск, свой DNS | — |
| 10 | все | финальные проверки + отчёт | — |

## Шаг 1. PVE (веб-интерфейс гипервизора), ~1 мин

1. Узел → System → Network: у `vmbr3` (HQ-SW) должно быть **VLAN aware = Yes**. Если нет: Edit → галочка → OK → **Apply Configuration**.
2. ВМ **HQ-SRV** → Hardware → Network Device (net0) → Edit → **VLAN Tag = 100** → OK.
3. ВМ **HQ-CLI** → Hardware → Network Device → Edit → **VLAN Tag = 200** → OK.
4. HQ-RTR **не трогаем**: без тега его порт на vmbr3 работает как trunk.

Тег применяется на лету, ВМ перезагружать не нужно.

## Шаг 2. ISP, ~2 мин + ⏳ загрузка

```bash
hostnamectl set-hostname isp; exec bash
sed -i 's/^HOSTNAME=.*/HOSTNAME=isp/' /etc/sysconfig/network

# ens19 (в интернет) → DHCP
sed -i 's/^BOOTPROTO=.*/BOOTPROTO=dhcp/' /etc/net/ifaces/ens19/options

# ens20 (к HQ-RTR), ens21 (к BR-RTR)
mkdir /etc/net/ifaces/ens20 /etc/net/ifaces/ens21
printf 'TYPE=eth\nBOOTPROTO=static\n' > /etc/net/ifaces/ens20/options
cp /etc/net/ifaces/ens20/options /etc/net/ifaces/ens21/options
echo 172.16.1.1/28 > /etc/net/ifaces/ens20/ipv4address
echo 172.16.2.1/28 > /etc/net/ifaces/ens21/ipv4address

# forwarding
sed -i 's/^net.ipv4.ip_forward = 0/net.ipv4.ip_forward = 1/' /etc/net/sysctl.conf

systemctl restart network
ip -br a ; ping -c2 77.88.8.8          # ✅ адреса на трёх интерфейсах + интернет

# ⏳ ЗАПУСКАЕМ ДОЛГОЕ и уходим на роутеры:
apt-get update && apt-get install -y iptables tzdata
```
➡️ **Не жди**, сразу переходи к HQ-RTR.

## Шаг 3. HQ-RTR: всё за один заход, ~5 мин

Логин по умолчанию: `admin` / `admin`.

```
enable
conf t
hostname hq-rtr
ip domain-name au-team.irpo
username net_admin
 password P@ssw0rd
 role admin
 exit
ntp timezone utc+3
!
! --- интерфейсы ---
interface isp
 ip address 172.16.1.2/28
 exit
interface vl100
 ip address 192.168.100.1/27
 exit
interface vl200
 ip address 192.168.200.1/24
 exit
interface vl999
 ip address 192.168.99.1/29
 exit
ip route 0.0.0.0/0 172.16.1.1
!
! --- привязка к портам ---
port te0
 service-instance te0/isp
  encapsulation untagged
  connect ip interface isp
  exit
 exit
port te1
 service-instance te1/vl100
  encapsulation dot1q 100 exact
  rewrite pop 1
  connect ip interface vl100
  exit
 service-instance te1/vl200
  encapsulation dot1q 200 exact
  rewrite pop 1
  connect ip interface vl200
  exit
 service-instance te1/vl999
  encapsulation dot1q 999 exact
  rewrite pop 1
  connect ip interface vl999
  exit
 exit
!
! --- GRE ---
interface tunnel.0
 ip address 10.10.10.1/30
 ip tunnel 172.16.1.2 172.16.2.2 mode gre
 ip ospf authentication message-digest
 ip ospf message-digest-key 1 md5 P@ssw0rd
 exit
!
! --- OSPF ---
router ospf 1
 ospf router-id 10.10.10.1
 passive-interface default
 no passive-interface tunnel.0
 network 10.10.10.0/30 area 0
 network 192.168.100.0/27 area 0
 network 192.168.200.0/24 area 0
 network 192.168.99.0/29 area 0
 exit
!
! --- NAT ---
interface isp
 ip nat outside
 exit
interface vl100
 ip nat inside
 exit
interface vl200
 ip nat inside
 dhcp-server 1
 exit
interface vl999
 ip nat inside
 exit
ip nat pool VLAN100 192.168.100.1-192.168.100.30
ip nat pool VLAN200 192.168.200.1-192.168.200.254
ip nat pool VLAN999 192.168.99.1-192.168.99.6
ip nat source dynamic inside-to-outside pool VLAN100 overload interface isp
ip nat source dynamic inside-to-outside pool VLAN200 overload interface isp
ip nat source dynamic inside-to-outside pool VLAN999 overload interface isp
!
! --- DHCP ---
ip pool VLAN200 192.168.200.2-192.168.200.254
dhcp-server 1
 pool VLAN200 1
  mask 24
  gateway 192.168.200.1
  dns 192.168.100.2
  domain-name au-team.irpo
  exit
 exit
write memory
```
Отступы только для наглядности, вводить их не нужно. Строки с `!` — комментарии, их не вводить.
Если `dhcp-server 1` на vl200 выдаст ошибку, что сервера ещё нет, повтори его **после** блока DHCP:
`interface vl200` → `dhcp-server 1` → `exit` → `write memory`.

✅ `show ip interface brief`: isp, vl100, vl200, vl999, tunnel.0 в статусе **up**. `ping 172.16.1.1` проходит.
(`ping 77.88.8.8` заработает, только когда ISP сделает NAT, т.е. после шага 5.)

## Шаг 5. Возврат на ISP (apt уже должен закончить), ~1 мин

```bash
iptables -t nat -A POSTROUTING -s 172.16.1.0/28 -o ens19 -j MASQUERADE
iptables -t nat -A POSTROUTING -s 172.16.2.0/28 -o ens19 -j MASQUERADE
iptables-save > /etc/sysconfig/iptables
systemctl enable --now iptables
timedatectl set-timezone Europe/Moscow
iptables -t nat -L POSTROUTING -n      # ✅ 2 правила MASQUERADE
```
✅ Теперь с HQ-RTR и BR-RTR проходит `ping 77.88.8.8`.

## Шаг 6. HQ-CLI, ~2 мин + ⏳ перезагрузка

1. **Терминал** → `su -` (пароль root) →
   ```bash
   timedatectl set-timezone Europe/Moscow
   ```
2. **ЦУС** (Центр управления системой) → Сеть → **Ethernet-интерфейсы**:
   - Имя компьютера: `hq-cli.au-team.irpo`;
   - ens19 → **Дополнительно…** → сетевая подсистема **NetworkManager (native)** → OK;
   - Конфигурация: **Использовать DHCP** → **Применить**.
3. **Перезагрузить** HQ-CLI (`reboot`).

➡️ ⏳ Пока грузится, иди на HQ-SRV. После загрузки проверь: Настройки → Сеть → Проводное (шестерёнка) → IPv4 = **Автоматический (DHCP)**, «Подробности»: 192.168.200.2 / шлюз .1 / DNS 192.168.100.2.

## Шаг 7. HQ-SRV, ~3 мин + ⏳ установка bind

```bash
hostnamectl set-hostname hq-srv.au-team.irpo; exec bash
sed -i 's/^HOSTNAME=.*/HOSTNAME=hq-srv.au-team.irpo/' /etc/sysconfig/network
timedatectl set-timezone Europe/Moscow

# сеть (проверь в options: BOOTPROTO=static, NM_CONTROLLED=no, DISABLED=no)
cat /etc/net/ifaces/ens19/options
echo 192.168.100.2/27          > /etc/net/ifaces/ens19/ipv4address
echo default via 192.168.100.1 > /etc/net/ifaces/ens19/ipv4route
echo nameserver 77.88.8.8      > /etc/net/ifaces/ens19/resolv.conf
systemctl restart network
ping -c2 77.88.8.8                      # ✅ интернет через 2 NAT

# ⏳ ЗАПУСКАЕМ ДОЛГОЕ (можно в фоне) и продолжаем тут же, пока качается
(apt-get update && apt-get install -y bind bind-utils) > /root/apt.log 2>&1 &

# пользователь
useradd sshuser -u 2026
passwd sshuser                          # P@ssw0rd ×2
usermod -aG wheel sshuser
echo 'sshuser ALL=(ALL:ALL) NOPASSWD: ALL' >> /etc/sudoers

# ssh
cat >> /etc/openssh/sshd_config <<EOF
Port 2026
AllowUsers sshuser
MaxAuthTries 2
Banner /etc/openssh/banner
EOF
echo 'Authorized access only' > /etc/openssh/banner
systemctl restart sshd
```
Параметры в `sshd_config` по умолчанию закомментированы, поэтому дописать их в конец файла можно. Если хочешь, как на sysahelper, раскомментируй и исправь их через `vim`.

➡️ Переходи на BR-SRV. bind качается в фоне (`tail /root/apt.log`, чтобы посмотреть).

## Шаг 9. HQ-SRV: DNS, ~4 мин

```bash
tail -3 /root/apt.log ; rpm -q bind          # убедиться, что bind установился
cd /var/lib/bind/etc
```

**options.conf**: три строки. Правим через sed и сразу проверяем:
```bash
sed -i -e 's|^\s*listen-on {.*|\tlisten-on { 192.168.100.2; };|' \
       -e 's|^\s*/*\s*forwarders {.*|\tforwarders { 77.88.8.8; };|' \
       -e 's|^\s*/*\s*allow-query {.*|\tallow-query { any; };|' options.conf
grep -nE 'listen-on|forwarders|allow-query' options.conf
```
✅ Должно получиться `listen-on { 192.168.100.2; };`, `forwarders { 77.88.8.8; };`, `allow-query { any; };`, **без** `//` в начале. Если какой-то строки нет, допиши её внутрь `options { … };` через `vim options.conf`.

**Зоны в rfc1912.conf:**
```bash
cat >> rfc1912.conf <<EOF

zone "au-team.irpo" { type master; file "au-team.irpo"; };
zone "100.168.192.in-addr.arpa" { type master; file "100.168.192.in-addr.arpa"; };
zone "200.168.192.in-addr.arpa" { type master; file "200.168.192.in-addr.arpa"; };
EOF
```

**Файлы зон** (из шаблона `empty`: берём его SOA и меняем localhost на наш домен):
```bash
cd zone
for z in au-team.irpo 100.168.192.in-addr.arpa 200.168.192.in-addr.arpa; do
  cp empty $z; sed -i 's/localhost\./au-team.irpo./g' $z
done

cat >> au-team.irpo <<EOF
@       IN A 192.168.100.2
hq-srv  IN A 192.168.100.2
hq-cli  IN A 192.168.200.2
hq-rtr  IN A 192.168.100.1
hq-rtr  IN A 192.168.200.1
hq-rtr  IN A 192.168.99.1
br-rtr  IN A 192.168.0.1
br-srv  IN A 192.168.0.2
docker  IN A 172.16.1.1
web     IN A 172.16.2.1
EOF

cat >> 100.168.192.in-addr.arpa <<EOF
1 IN PTR hq-rtr.au-team.irpo.
2 IN PTR hq-srv.au-team.irpo.
EOF

cat >> 200.168.192.in-addr.arpa <<EOF
1 IN PTR hq-rtr.au-team.irpo.
2 IN PTR hq-cli.au-team.irpo.
EOF

cat au-team.irpo      # ✅ SOA "au-team.irpo. root.au-team.irpo.", NS "au-team.irpo."
```

**rndc, права, проверка, запуск:**
```bash
rndc-confgen > /var/lib/bind/etc/rndc.key
sed -i '6,$d' /var/lib/bind/etc/rndc.key
chown -R root:named /var/lib/bind/etc/zone/*
named-checkconf && named-checkconf -z | grep -E 'au-team|168.192'   # ✅ 3 зоны "loaded serial"
systemctl enable --now bind
```

**Перевести HQ-SRV на свой DNS:**
```bash
printf 'search au-team.irpo\nnameserver 192.168.100.2\n' > /etc/net/ifaces/ens19/resolv.conf
systemctl restart network
host hq-rtr.au-team.irpo ; host 192.168.200.2 ; ping -c2 ya.ru      # ✅
```

**HQ-CLI** (уже загрузился):

```bash
host br-srv.au-team.irpo ; host 192.168.100.2 ; ping -c2 ya.ru

```

**HQ-RTR:**
```
show ip ospf neighbor              ! Full
show ip route                      ! O 192.168.0.0/28 via 10.10.10.2
show dhcp-server clients vl200     ! 192.168.200.2
show ip nat translations
```

**HQ-SRV / BR-SRV:**
```bash
ssh -p 2026 sshuser@localhost      # баннер → вход → sudo -i без пароля
```

Если что-то не работает, типовые причины:

| Симптом | Где смотреть |
|---|---|
| HQ-SRV не пингует 192.168.100.1 | тег 100 в PVE; SI `dot1q 100 exact` + `rewrite pop 1` на te1 |
| Роутеры не выходят в интернет | ISP: `sysctl net.ipv4.ip_forward`, `iptables -t nat -L -n` |
| Серверы не выходят в интернет, роутеры выходят | NAT на RTR: `ip nat inside/outside`, pool |
| Нет OSPF-соседа | разные ключ/пароль MD5, забыт `no passive-interface tunnel.0` |
| HQ-CLI без адреса | `dhcp-server 1` на vl200; NM native; тег 200 |
| bind не стартует | `named-checkconf -z`, `journalctl -u bind`, `//` перед forwarders, права `root:named` |

**Отчёт** (адреса, VLAN, GRE, OSPF, DHCP) удобно заполнять во время ⏳-пауз. Таблицы есть в основной методичке.
